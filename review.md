Первоначальное ревью — вариант 7

R01. Неверный подсчёт недоступных узлов

Файл: `ReviewTask.cs`, строка с условием `if (value)`  

Требование: `true` означает доступный узел, а `false` — недоступный. Метод должен считать только недоступные узлы.

Вход: `available = [true, true]`.

Ожидаемый результат: `0`, так как все узлы доступны.

Фактический результат: `100`.

Причина: Счётчик `down` увеличивается при `value == true`, поэтому метод считает доступные узлы вместо недоступных.

Предложение по исправлению: Изменить условие на `if (!value)`.

Проверка после исправления: T03 и T04.

R02. Неверный порядок арифметических операций

Файл: `ReviewTask.cs`, строка с выражением `down / available.Length * 100`  

Требование: Возвращать целый процент недоступных узлов с округлением вниз.

Вход: `available = [false, true, true, true]`.

Ожидаемый результат: `25`.

Фактический результат: `0`.

Причина: При делении целых чисел `1 / 4` получается `0`. Последующее умножение на `100` не восстанавливает потерянную дробную часть.

Предложение по исправлению: Умножать количество недоступных узлов на `100` до целочисленного деления: `down * 100 / available.Length`.

Проверка после исправления: T01 и T02.

R03. Не обрабатывается пустой массив

Файл: `ReviewTask.cs`, строка с выражением `down / available.Length`  

Требование: Пустой массив должен давать `0`.

Вход: `available = []`.

Ожидаемый результат: `0`.

Фактический результат: Исключение `DivideByZeroException`.

Причина: Для пустого массива `available.Length == 0`, поэтому происходит деление на ноль.

Предложение по исправлению: До вычисления процента проверить длину массива и вернуть `0`, если она равна нулю.

Проверка после исправления: T05.
